Hybrid Serving Atlas

Edge-Cloud 推理编排

围绕 Copilot 推理热路径，构建一个像云数据库一样可调度、可治理的 Hybrid Serving 平台，支撑 edge-cloud 协同的 sub-50ms SLA。

  • Duration · 2024 Q2 - 2025 Q1
  • Role · Research Engineer / Systems Designer
  • Stack · Rust Runtime · ONNX Runtime · Azure Arc

研究摘要：提出热路径意识（Hot-Path Awareness）与缓存分层（KV Cache Tiering）联合的调度策略，并通过自监督遥测构建可验证的服务品质模型。

交付物：包含论文式技术文档、指标仪表板、以及 Terraform 自动化部署脚本。

研究动机 / Abstract

随着 Copilot 使用场景向 offline/edge 延展，单一云端推理无法满足实时性与可靠性。Hybrid Serving Atlas 用“数据库式优化”类比推理编排，让每一次 LLM 调用都可解释、可治理。

  • 将推理请求视作 SQL Query，构建 Plan Cache 与 Cost Model。
  • 结合边缘设备（ARM SoC）与云 GPU/CPU 的异构资源，支持弹性拓扑。

方法论 / Methodology

  • Hot-Path Scheduler：对历史查询构建 KV-Cache 热度直方图，驱动优先级调度。
  • Tiered Cache Fabric：在 edge、regional cache、cloud 三层之间复制 Token 片段。
  • 绿色算力策略：根据碳强度 API 动态迁移非关键任务到低碳 region。

实验设计 / Experiment

  • 基准：Mixtral-8x7B / Phi-3-mini，输入 2K tokens，批量 8。
  • 对照组：纯云端 GPU 服务；实验组：Hybrid Serving。
  • 指标：P95 延迟、缓存命中率、能耗/请求。

结果与指标

  • P95 延迟从 132ms 降至 48ms；缓存命中率 71% → 93%。
  • 能耗/请求下降 22%，原因是 ARM 侧预处理 + 云侧批量推理。
  • 故障恢复时间（MTTR） < 90s，得益于多副本热切换。

交付物 / Deliverables

  • Hybrid Serving Atlas 白皮书（35 页），包含证明与伪代码。
  • Grafana + Observable 制作的遥测仪表板，支持讲述式演示。
  • Terraform 模块：自动部署 edge gateway、cache、云端推理。

下一步

计划将 Cost Model 接入 reinforcement tuning，让调度策略可以随业务目标自适应；并把 Carbon Aware API 纳入 runtime 约束。
